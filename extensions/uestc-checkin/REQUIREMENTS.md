# uestc-checkin 项目要求

更新日期：2026-10-21

## 本次调整范围

按用户最新要求，将已通过本地真实签到验收的 Docker 项目部署到腾讯云，启用云端定时执行。运行、测试和调试依赖均在 Docker 内，不使用本机 Chrome 执行正式任务。初期不使用数据库，状态保存为 JSON。复用既有 NapCat、AstrBot，不重启或重新登录机器人。

本文件是执行环境和验收要求的依据；README 中与本文件冲突的本地运行说明属于旧版 MVP 的历史说明，不能作为后续实施方案。

## 云端执行目标

- 腾讯云 Lighthouse Linux 服务器是项目运行环境。登录、会话维护、页面访问、状态检查、定时调度、重试、日志和 QQ 通知均在云端执行。
- 开发验证、自动化测试和运行验收应能在云端独立完成，不要求用户电脑安装 Python、Playwright 或 Chromium。
- 用户电脑关闭、断网或退出浏览器后，云端任务仍能按计划运行。
- 不依赖本地常驻进程、本地浏览器、个人 Chrome profile、本地定时器，或从用户电脑持续同步 Cookie、Token 和会话文件。
- 凭证通过云端受控配置注入；会话、任务锁和必要运行数据保存在云端持久化目录，容器重建后可恢复。凭证和会话不得写入镜像、Git 或日志。

## 登录与人工处理

- 首次登录、有效性检查、自动重新认证和会话保存均以云端独立浏览器会话为目标。
- 本地有界面浏览器的 `manual-login` 以及本地 profile 导入不再作为必需步骤或默认恢复方案。
- 遇到验证码、短信或二次认证时暂停自动认证，并通过云端通知请求人工处理；后续需设计并验证受控的云端交互方案。用户可通过终端或浏览器访问云端管理入口提供必要输入，任务与会话仍在云端执行。
- 日常无头执行，不部署完整桌面环境；首次登录允许按需启用容器内 Xvfb/noVNC，通过回环地址访问。此项取代旧版禁止 VNC 的限制。不绕过验证码或认证校验。

## 资源与现有服务

- 沿用现有 2GB 内存服务器、Docker Compose 和 Asia/Shanghai 时区要求。
- 浏览器按任务启动并及时关闭，同一时刻最多执行一个浏览器任务，具备超时、任务锁和有限重试。
- 上线前在云端确认资源余量并实测峰值占用，不影响现有 NapCat、AstrBot。
- QQ 通知优先复用现有服务；接口、端口、Token 和网络配置须根据实际部署确认。

## 业务范围与待验证事项

- 用户目标为：容器浏览器登录学校账号 → Playwright 内置定位 → 按页面流程签到 → 重新读取今日签到记录 → NapCat 私聊通知。此项替代旧版仅查询与提醒的范围；本地 Docker 已于 2026-10-21 完成真实提交验收，云端须独立验证会话、定位、复查和通知。当天已成功时，云端应跳过重复提交，不清除成功状态以强行测试。
- 学校真实认证、业务授权、微信小程序票据以及定位要求仍需实际验证，不将用户设备上的成功访问视为云端验证结果。
- 若学校要求真实在场或用户通过官方客户端操作，应通知用户完成必要操作，云端负责可支持的查询与复查；将此类外部人工步骤与系统的云端执行范围明确记录。
- 定位采用 Playwright 内置 Geolocation，不引入第三方定位扩展；不把浏览器坐标设置成功等同于服务端接受。微信授权票据、额外设备或位置校验不在已验证能力内，遇到时记录限制，不声称签到成功。

## 后续验收标准

1. 仅使用云端代码、配置和持久化数据即可完成安装、测试与启动。本次迁移允许一次性导入专用 Docker 浏览器会话；后续登录、会话恢复及认证均在云端容器完成，不依赖本地持续同步。
2. 在用户电脑离线条件下，定时检查、会话恢复、有限重试和通知正常执行。
3. 云端容器重启或重建后会话与暂停状态保留，不产生重复任务或循环登录。
4. 认证需人工介入时暂停并通知，可用的云端处理流程经验证；尚未支持的情况明确标记为阻塞。
5. 在目标服务器上验证资源占用以及与现有机器人的并行运行情况。
6. 分别记录 Mock 测试和学校真实端到端验证的结果，未验证项不得标记完成。
