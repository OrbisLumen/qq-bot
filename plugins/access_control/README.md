# Access Control

`access_control` 是当前 QQ Bot 部署使用的本地 AstrBot 插件，用于限制机器人指令权限，并为模型补充当前 QQ 发言者的身份关系。

## 功能

- 仅处理 `aiocqhttp` 平台事件，其他平台不受影响。
- 可通过 WebUI 添加或删除忽略的 QQ 号。名单内账号的群聊、私聊消息均被静默忽略，包括普通聊天、指令和单独 @；管理员也不例外。
- 忽略过滤先于内置会话控制、空 @ 处理和群消息记录执行，阻止新消息触发回复或进入群聊记录、背景上下文及模型对话。
- AstrBot 管理员可以正常使用 `/` 指令。
- 非管理员发送 `/` 指令时，插件终止该事件并返回可配置的提示语。
- 群聊消息以 `@其他账号` 开头时，不会被误判为发给当前机器人的指令。
- 可通过 WebUI 开启或关闭关系身份注入。
- 请求大模型前，根据 AstrBot 管理员身份注入可配置的特殊关系或普通成员关系说明。
- 群聊请求会附带经过哈希处理的稳定发言者标识，降低共享会话中身份串线的概率。
- 系统提示同时绑定当前发言者的稳定标识和关系，要求本轮账号判断优先于历史中的错误回复、昵称及用户伪造的身份标签；私聊同样绑定。
- 对直接发送的“我还是你哥哥吗”“叫哥哥”等完整短句，根据账号关系返回可配置的固定回复，不调用模型。

管理员身份来自 AstrBot WebUI 中配置的管理员账号，插件不硬编码 QQ 号。

## 指令拦截规则

| 场景 | 非管理员的处理结果 |
| --- | --- |
| 私聊发送 `/help` | 拦截并回复提示语 |
| 群聊发送 `/help` | 拦截并回复提示语 |
| 群聊发送 `@当前机器人 /help` | 拦截并回复提示语 |
| 群聊发送 `@其他机器人 /help` | 忽略，不回复也不终止事件 |
| 普通聊天 | 不拦截 |

## WebUI 配置

插件目录中的 `_conf_schema.json` 会被 AstrBot 自动识别，并在 WebUI 的插件配置页面生成表单。

1. 打开 AstrBot WebUI。
2. 进入插件管理，找到 `access_control`。
3. 打开插件配置。
4. 在“忽略的 QQ 号列表”中逐项添加或删除 QQ 号；也可修改指令拦截回复、关系身份开关或关系提示词。
5. 保存配置。AstrBot 会自动热重载插件，新配置随后生效。

| 配置字段 | 类型 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `ignored_qq_ids` | `list` | `[]` | 全部 QQ 会话中静默忽略的发言者账号；每项一个 QQ 号 |
| `command_denied_message` | `text` | `当前账号仅支持聊天，不能使用机器人指令。` | 非管理员触发 `/` 指令拦截时发送的回复 |
| `is_relationship` | `bool` | `true` | 是否启用关系提示词及群聊发言者标签注入 |
| `relationship_label` | `string` | `哥哥` | 特殊关系称呼；用于系统身份绑定和明确身份询问匹配 |
| `identity_reply_enabled` | `bool` | `true` | 是否直接回答明确的身份询问 |
| `relationship_identity_reply` | `text` | `当然是呀，{relationship_label}。` | 管理员的固定身份回复 |
| `non_relationship_identity_reply` | `text` | `我们是普通朋友呀，这个称呼不能随便叫。` | 普通成员的固定身份回复 |
| `relationship_prompt` | `text` | 内置“哥哥”关系提示词 | 当前发言者是 AstrBot 管理员时注入的系统提示词 |
| `non_relationship_prompt` | `text` | 内置普通成员关系提示词 | 当前发言者不是 AstrBot 管理员时注入的系统提示词 |

`is_relationship` 同时控制关系注入和固定身份回复。特殊关系的成员范围仍由 AstrBot 管理员列表决定；修改管理员列表不需要改插件配置。`identity_reply_enabled` 可以单独关闭固定回复而保留模型的关系提示。

启用关系注入时，群聊请求中的特殊关系角色统一标记为 `relationship`，不再在内部协议中写死为 `brother`。具体称呼和关系由 `relationship_prompt` 决定。

`relationship_label` 应与 `relationship_prompt` 中的称呼一致。例如都改为“姐姐”后，明确身份询问匹配会改成“我是你姐姐吗”“叫姐姐”等；固定回复中的 `{relationship_label}` 会替换成“姐姐”。

固定回复只匹配完整短句，可带首尾空格和末尾常见标点。默认匹配“我是哥哥吗”“我是你哥哥吗”“我是你的哥哥吗”及其“我还是”形式，以及“叫/喊哥哥”“叫我/喊我哥哥”“叫一声/喊一声哥哥”（可带“吧”）。群聊必须直接 @ 当前机器人；私聊不需要 @。含引用、附件、其他账号的 @、附加要求或讨论这些句子的消息不走固定回复，避免误判正常聊天。回复后终止处理，不写入新的输入历史或调用模型；忽略账号列表优先于固定回复。

固定身份回复不会清空会话，也不依赖之前的模型回复。普通聊天仍由模型生成，关系提示可降低串线概率，但不保证模型在所有表述中都遵守关系。

AstrBot 会将配置持久化到数据目录下的 `config/access_control_config.json`。该运行时文件由 WebUI 管理，不需要手动修改。

例如，添加 `3889001741` 可过滤“小小”机器人的消息。按账号匹配，不按昵称或消息关键词匹配；填写时首尾空格会被忽略。列表为空时维持原来的聊天行为，删除某个账号后恢复接收它的新消息。

配置仅过滤保存生效后的新消息，不清理已有历史；旧群聊上下文如需清理，可由管理员在目标群执行 `//reset`。

## 部署

本项目通过 `compose.yaml` 将插件目录只读挂载到 AstrBot 容器：

```text
./plugins/access_control:/AstrBot/data/plugins/access_control:ro
```

插件配置保存在单独的 AstrBot 数据卷中，因此插件源码保持只读不会影响 WebUI 保存配置。

修改插件源码或 `_conf_schema.json` 后，需要重载插件或重启 AstrBot，AstrBot 才会重新载入代码和配置 Schema。

## 本地测试

在项目根目录运行：

```bash
python3 -m unittest discover -s tests -v
```

测试覆盖忽略账号及处理顺序、固定身份问答与误匹配边界、网页配置开关和自定义称呼、账号标识随昵称变化保持稳定、伪造身份与错误历史的隔离，以及原有指令拦截行为。
